# گزارش نسخهٔ قابل آزمایش Paymoon

این نسخه جریان اصلی تجارت اجتماعی را در پروژهٔ محلی `/Users/mahdi/Documents/projects/Paymoon` پیاده می‌کند. ظاهر فارسی و RTL از الگوهای ناوبری، پروفایل، فید، شبکهٔ تصاویر و ایجاد پست Instagram الهام گرفته است؛ نام و هویت محصول Paymoon باقی می‌ماند.

## امکانات پیاده‌شده

### اپ خریدار — marketplace

- مشاهدهٔ محصولات منتشرشدهٔ فروشگاه‌های تأییدشده؛ فید و شبکهٔ تصاویر.
- جست‌وجوی عنوان و توضیح، دسته‌بندی، مرتب‌سازی قیمت و صفحه‌بندی.
- صفحهٔ محصول، انتخاب رنگ/سایز یا مدل، قیمت و موجودی.
- پروفایل فروشگاه، شرایط ارسال و مرجوعی و نظر خریداران واقعی سفارش.
- ذخیرهٔ محصول، دنبال‌کردن فروشگاه و مشاهدهٔ فهرست‌های شخصی.
- سبد یک فروشگاه، تغییر تعداد، حذف کالا و انتخاب نشانی.
- محاسبهٔ قیمت در سرور، ثبت سفارش و رزرو موجودی برای ۳۰ دقیقه.
- صفحهٔ پیگیری سفارش، لغو پیش از پرداخت، کد رهگیری، تأیید دریافت و ثبت نظر.
- ورود و ثبت‌نام، حساب، نشانی‌ها، اعلان‌ها، درخواست پشتیبانی و مشاهدهٔ پاسخ.
- راهنما، شرایط استفاده و توضیح حریم خصوصیِ نسخهٔ آزمایشی.

### اپ فروشنده — seller

- ساخت سازمان و فروشگاه، راه‌اندازی اولیه و ارسال برای بررسی مدیریت.
- انتخاب فروشگاه فعال برای حساب‌های دارای چند عضویت.
- داشبورد با آمار واقعی محصول، سفارش، خریدار و مجموع سفارش‌های پرداخت‌شده.
- ساخت و ویرایش محصول؛ عکس، توضیح، دسته، مدل‌های مختلف، رنگ/سایز و قیمت به تومان.
- آپلود JPG/PNG/WebP تا ۵ مگابایت؛ اعتبارسنجی امضای واقعی فایل و ذخیرهٔ محلی با نام مبتنی بر هش.
- پیش‌نویس، انتشار و آرشیو؛ انتشار نیازمند قیمت مثبت، تصویر و تأیید فروشگاه است.
- کنترل نسخهٔ محصول برای جلوگیری از بازنویسی تغییرات هم‌زمان.
- انبار با موجودی قابل فروش، رزرو و تعهد؛ ثبت ورود کالا و جابه‌جایی خودکار در مسیر سفارش.
- آماده‌سازی سفارش پرداخت‌شده و ثبت شرکت ارسال و کد رهگیری.
- تنظیم معرفی، هزینهٔ ارسال ثابت، زمان ارسال و شرایط مرجوعی.
- افزودن حساب ثبت‌شدهٔ همکار با ایمیل و نقش مدیر/همکار/مشاهده‌گر؛ تغییر یا حذف دسترسی فقط توسط مالک.
- دفتر مالی دوبل، اعلان‌های فروشگاه و پشتیبانی.

### پنل مدیریت — admin

- دسترسی محدود به UUIDهای تعیین‌شده در محیط سرور، مستقل از نقش سازمان.
- نمای کلی، بررسی و تأیید/رد فروشگاه، فهرست سفارش‌ها.
- مشاهدهٔ وضعیت outbox و inbox بدون نمایش توکن Meta.
- پاسخ به درخواست پشتیبانی و گزارش شمارش رویدادهای محصول.

### اتصال رسمی Instagram

مسیر **Instagram API with Instagram Login** برای حساب حرفه‌ای صاحب فروشگاه آماده است. این روش ورود خریدار به Paymoon نیست؛ اجازهٔ دریافت محتوای فروشنده است.

- درخواست اتصال از حساب واردشده و عضو مجاز فروشگاه.
- لینک کوتاه‌عمر و یک‌بارمصرف برای انتقال از APK به مرورگر سیستم؛ توکن Paymoon داخل URL قرار نمی‌گیرد.
- OAuth state با اتصال به مرورگر، نشست، نقش و سازمان؛ بررسی مجدد مجوز پیش از ثبت اتصال.
- تبادل کد، توکن بلندمدت و ذخیرهٔ رمزنگاری‌شدهٔ توکن در سرور.
- مشاهدهٔ وضعیت، همگام‌سازی پست‌ها با cursor، تمدید و قطع اتصال.
- انتخاب پست و تبدیل به پیش‌نویس؛ ایمپورت تکراری محصول دوباره نمی‌سازد.
- عنوان/توضیح از کپشن و تصویر/thumbnail از رسانه؛ قیمت و موجودی عمداً صفر می‌ماند تا فروشنده تکمیل کند.
- امکان «نگهداری دائمی عکس‌های اینستاگرام» در محصول واردشده: کپی فقط از میزبان‌های رسمی Meta، با سقف حجم و زمان، بدون دنبال‌کردن redirect.
- تأیید و دریافت webhook با امضای Meta، inbox تکرارناپذیر و نسبت‌دادن به فروشگاه متصل.
- فعال‌سازی اعلان کامنت/پیام فقط در صورت وجود مجوز مناسب؛ صندوق پیام و ارسال پاسخ کامل پیاده نشده است.

اتصال واقعی Meta با حساب واقعی هنوز آزمایش نشده است. تست‌ها از پاسخ‌های کنترل‌شدهٔ adapter استفاده می‌کنند. مرجع رسمی: [مجموعهٔ Instagram API منتشرشده توسط Meta](https://www.postman.com/meta/instagram/folder/6raa77c/instagram-api-with-instagram-login).

## ساختار

```text
apps/
  marketplace/   Next.js + Android Capacitor
  seller/        Next.js + Android Capacitor
  admin/         Next.js
  api/           NestJS + Fastify، modular monolith
  worker/        BullMQ، outbox/inbox و انقضای سفارش
  ai-service/    scaffold اختیاری
packages/
  ui/ db/ auth/ contracts/ config/ logger/ events/
  validation/ money/ observability/ testing/
.telemetry/      مدل محصول، طرح رویدادها و راهنمای ثبت
```

قراردادهای نمایش بین اپ‌ها مشترک‌اند. کد frontend به پایگاه داده یا کلیدهای Meta دسترسی مستقیم ندارد. احراز وب با cookie از نوع HttpOnly و بررسی Origin برای تغییرات انجام می‌شود؛ در Android، توکن فقط در Secure Storage بومی قرار می‌گیرد. ذخیرهٔ توکن در localStorage وب انجام نمی‌شود.

## اجرا

Node طبق `.nvmrc` و pnpm طبق `packageManager` پروژه نصب باشند.

```bash
cd /Users/mahdi/Documents/projects/Paymoon
pnpm install --frozen-lockfile
# فقط در اولین راه‌اندازی، وقتی .env موجود نیست:
cp .env.example .env
pnpm infra:up
pnpm build
pnpm db:migrate
pnpm dev
```

پورت‌های پیش‌فرض: marketplace روی 4100، seller روی 4101، admin روی 4102، API روی 4000 و health worker روی 4001. Swagger در `http://localhost:4000/docs` و سند OpenAPI در `/openapi.json` است. برای اجرای جداگانه، از `pnpm --filter @paymoon/<نام اپ> dev` استفاده کنید؛ نام API برابر `commerce-api` و worker برابر `worker` است.

برای اجرای تست‌های یکپارچه، دیتابیس جدا با نام پایان‌یافته به `_test` و Redis تست معرفی کنید. این دیتابیس باید پیش از تست migrate شود.

```bash
COMMERCE_DATABASE_URL='postgresql://...' pnpm db:migrate
COMMERCE_DATABASE_TEST_URL='postgresql://.../paymoon_test' \
COMMERCE_REDIS_TEST_URL='redis://localhost:56379/1' pnpm test
pnpm lint
pnpm typecheck
pnpm build
```

## envهای لازم

| نام                                                      | کاربرد                                                                                            |
| -------------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| `COMMERCE_DATABASE_URL`                                  | PostgreSQL اصلی؛ Docker محلی روی 55432                                                            |
| `COMMERCE_REDIS_URL`                                     | Redis اصلی؛ Docker محلی روی 56379                                                                 |
| `COMMERCE_API_PORT` / `COMMERCE_WORKER_PORT`             | پورت سرویس‌ها                                                                                     |
| `COMMERCE_CORS_ORIGINS`                                  | مبداهای دقیق marketplace، seller، admin و Android؛ شامل `https://localhost` برای Capacitor        |
| `NEXT_PUBLIC_API_URL`                                    | نشانی API برای frontend؛ هنگام build در وب/APK قرار می‌گیرد                                       |
| `COMMERCE_API_PUBLIC_URL`                                | نشانی عمومی API برای تصاویر و لینک ورود Meta                                                      |
| `COMMERCE_MEDIA_DIR`                                     | پوشهٔ تصاویر، پیش‌فرض `../../var/media` نسبت به اپ API؛ در سرور مسیر مطلق و فضای پایدار تعیین شود |
| `COMMERCE_ADMIN_USER_IDS`                                | UUIDهای مدیر پلتفرم، جداشده با کاما؛ حساب باید ابتدا ثبت شود                                      |
| `COMMERCE_PAYMENT_MODE`                                  | پیش‌فرض `disabled`؛ برای تست توسعه `sandbox`؛ در production حالت sandbox ممنوع است                |
| `NODE_ENV` / `LOG_LEVEL`                                 | محیط اجرا و سطح گزارش                                                                             |
| `COMMERCE_DATABASE_TEST_URL` / `COMMERCE_REDIS_TEST_URL` | فقط تست یکپارچه                                                                                   |

برای Instagram:

```dotenv
INSTAGRAM_APP_ID=شناسه_Instagram_اپ_Meta
INSTAGRAM_APP_SECRET=secret_همان_اپ
INSTAGRAM_API_VERSION=نسخه_پشتیبانی_شده_مثل_v25.0
INSTAGRAM_REDIRECT_URI=https://api.YOUR-DOMAIN/v1/instagram/oauth/callback
INSTAGRAM_TOKEN_ENCRYPTION_KEY=کلید_۶۴_کاراکتری_hex
INSTAGRAM_SCOPES=instagram_business_basic
INSTAGRAM_VERIFY_TOKEN=رشته_تصادفی_بلند_برای_webhook
```

این نمونه توضیحی است؛ مقادیر نمونه را عیناً کپی نکنید. کلید رمزنگاری را با `openssl rand -hex 32` بسازید و نگهدارید. تغییر کلید، توکن‌های قبلی را غیرقابل خواندن می‌کند و نیاز به اتصال مجدد دارد. شناسهٔ Instagram App ID/Secret را از تنظیمات همان محصول Instagram Login بردارید. نسخهٔ API را با اپ خود در Meta تطبیق دهید.

برای اعلان کامنت یا پیام، scopeهای `instagram_business_manage_comments` و `instagram_business_manage_messages` را تنها همراه با مجوز واقعی اپ اضافه کنید و حساب را دوباره متصل کنید.

در Meta باید callback بالا، URL وب‌هوک `https://api.YOUR-DOMAIN/v1/instagram/webhook` و verify token مطابق محیط ثبت شوند. سرور باید از اینترنت با HTTPS قابل دسترس باشد. پرکردن `.env` به‌تنهایی جای تنظیم اپ Meta، حساب حرفه‌ای و مجوزهای لازم را نمی‌گیرد. وب و API برای cookie وب باید روی یک site مشترک، مثلاً زیردامنه‌های همان دامنه، باشند.

## migrationها

migrationهای 0001 تا 0003 حفظ شده‌اند. اجرای migration با checksum و قفل تراکنشی انجام می‌شود؛ migration قدیمیِ اعمال‌شده را ویرایش نکنید.

- `0004_product_release.sql`: توضیح و تصاویر و نسخهٔ محصول، تنظیم ارسال فروشگاه، خطوط و نشانی ثابت سفارش، نشانی‌ها، ذخیره/دنبال‌کردن، نظرات، پشتیبانی، اعلان خریدار، رویدادهای محصول، ticket ورود موبایل و دسته‌های اولیه.
- `0005_product_indexes.sql`: indexهای محصول، سفارش، پشتیبانی و نگهداری رویداد؛ محدودیت آرایه‌بودن تصاویر.

Worker سفارش پرداخت‌نشدهٔ منقضی را لغو و رزرو را آزاد می‌کند. بدون worker، رزروهای منقضی خودکار آزاد نمی‌شوند. رویدادها تراکنشی‌اند؛ اجرای تکراری checkout ثبت سفارش یا analytics تکراری نمی‌سازد. رویدادهای محصول پس از ۹۰ روز پاک می‌شوند و هیچ مقصد تحلیل بیرونی فعال نیست.

## APK

```bash
# نیازمند JDK 21 و Android SDK
JAVA_HOME=/path/to/jdk-21 \
ANDROID_HOME=/path/to/android-sdk pnpm android:apk
```

خروجی هر اپ در `apps/<app>/android/app/build/outputs/apk/debug/` ساخته می‌شود. APKها debug هستند؛ برای انتشار عمومی باید با کلید انتشار امضا شوند. APK فعلی با نشانی پیش‌فرض API محلی ساخته می‌شود؛ `localhost` گوشی، رایانهٔ شما نیست. پس از تعیین نشانی عمومی HTTPS، `NEXT_PUBLIC_API_URL` و `COMMERCE_API_PUBLIC_URL` را تنظیم و APK را دوباره بسازید. مجوز cleartext و تضعیف TLS برای حل این موضوع فعال نشده است.

## حدود واقعی این نسخه

این یک نسخهٔ قابل آزمایش از جریان اصلی محصول است، نه ادعای آماده‌بودن کل پلتفرم برای پول و مشتری واقعی. موارد زیر هنوز تکمیل نشده‌اند:

- درگاه واقعی، callback تأییدشدهٔ بانکی، escrow/حفاظت مالی، تسویه و بازپرداخت واقعی؛ interface درگاه آماده است.
- صندوق پیام و پاسخ‌دهی کامل Instagram؛ فعلاً دریافت webhook و اعلان آماده است.
- جست‌وجوی هوشمند با عکس/لینک دلخواه، استخراج قابل اعتماد قیمت از کپشن و رتبه‌بندی با AI.
- فرایند کامل مرجوعی/اختلاف، ورود OTP و بازیابی رمز، ارسال SMS/email/push، قراردادهای حقوقی عرضهٔ عمومی.
- استقرار عمومی، backup عملیاتی، ذخیرهٔ تصاویر روی object storage و آزمایش APK روی دستگاه واقعی.

قدم بعدیِ مشخص: تنظیم یک سرور HTTPS و اپ Meta، اتصال یک حساب حرفه‌ای آزمایشی از seller، همگام‌سازی و ایمپورت یک پست، نگهداری تصویر، تکمیل قیمت و موجودی و انتشار. سپس درگاه واقعی به interface پرداخت اضافه و مسیر مالی با sandbox همان ارائه‌دهنده تست شود.

## نتیجهٔ بررسی نهایی — ۷ اکتبر ۲۰۲۶

- `pnpm lint`: موفق؛ ۱۶ task.
- `pnpm typecheck`: موفق؛ ۲۶ task.
- `pnpm build`: موفق؛ ۱۶ task، شامل هر سه frontend و API و worker.
- تست‌های دیتابیس/Redis جداگانه: ۱۶ تست، بدون failure و بدون skip. پوشش شامل رقابت checkout و عدم فروش بیشتر از موجودی، replay سفارش و پرداخت، دفتر دوبل، جداسازی خریدار و سازمان، انقضای رزرو، cookie/CSRF، OAuth و import با پاسخ‌های کنترل‌شده و inbox/outbox است.
- تست مرورگر با دادهٔ ساختگی: ایجاد فروشگاه و محصول، ویرایش و انتشار، ورود موجودی ۵ واحد، سبد، نشانی، ثبت سفارش، لغو و بازگشت موجودی به ۵ available / ۰ reserved / ۰ committed. محصول آزمایشی پس از بررسی آرشیو شد.
- migrationهای 0001 تا 0005 روی توسعه و تست ثبت و تأیید شدند؛ دیتابیس موجود reset نشد.
- APK هر دو اپ ساخته شد؛ شناسه‌های `com.paymoon.marketplace` و `com.paymoon.seller`، حداقل Android API 24 و target API 36. امضای debug با apksigner تأیید شد.
- اتصال زندهٔ Meta، پرداخت بانکی و اجرا روی دستگاه Android واقعی هنوز آزمایش نشده‌اند.

دو APK همراه این گزارش برای بررسی نسخهٔ ساخته‌شده هستند. برای استفاده روی گوشی، ابتدا نشانی HTTPS API را تعیین و خروجی Android را دوباره بسازید؛ تغییر `.env` بدون build مجدد نشانی API داخل APK را تغییر نمی‌دهد.
